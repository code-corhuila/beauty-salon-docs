# Internationalization (i18n)

## Rules

- **No hardcoded user-facing strings.** All copy comes from resource/localization files.
- Reference strings by key, never by literal text, in screens.
- Format dates, numbers, and currency with **locale-aware** APIs — never manual formatting.
- Support **RTL** layouts: use start/end (not left/right) for directional spacing and alignment.
- Handle pluralization through the platform's plural rules, not string concatenation.
- Keep keys namespaced by feature: `checkout.button.pay`, `login.error.invalid`.

## Workflow

1. Add the key + default-language value to the resource file.
2. Reference the key in the UI.
3. Provide translations per supported locale.
4. Never ship a key without at least the default-language value.

## Checklist

- [ ] No literal user-facing strings in code.
- [ ] Dates/numbers/currency formatted per locale.
- [ ] Layout verified in an RTL locale.
- [ ] Long translations do not overflow (test with a verbose locale, e.g. German).
